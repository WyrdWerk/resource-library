### archify
- Details: Archify is an agent skill that turns descriptions or entire repositories into beautiful, verifiable architecture, workflow, sequence, data-flow, and lifecycle diagrams as self-contained HTML with motion and crisp PNG export. You describe the idea to your coding agent (it installs via npx skills add and works with Cursor, Claude Code, Codex CLI, and OpenCode), then refine in chat with requests like "highlight the cache-miss path" or "switch to the light theme". The output is a standalone HTML file you can open, explore, and share with no installation needed, and a Proof Lab ships checked-in scenarios with validation receipts. MIT licensed, it hit number one on GitHub Trending's weekly all-language list.

### beads-rust
- Details: beads_rust (command name br) is a fast Rust port of Steve Yegge's beads, frozen at the classic SQLite plus JSONL architecture, by Jeffrey Emanuel with Yegge's endorsement. It is a local-first, non-invasive issue tracker for git repositories: issues live in a local SQLite database with JSONL export for git-friendly collaboration, supporting dependencies, priorities, labels, and machine-readable JSON output designed for AI coding agents. The design philosophy is explicit over implicit — it never commits, pushes, or runs background services — with commands like br ready to surface actionable work and br sync to reconcile state after merges. Install via a curl script, Homebrew, Scoop, or cargo.

### loop-library-forwardfuture-signals
- Details: The ForwardFuture Signals Loop Library is a searchable collection of 85 copy-paste prompts called loops: repeatable AI agent workflows with clear checks and stopping conditions. Each loop encodes a full operational procedure — for example the production error sweep (find, fix, verify, open a PR), the docs sweep (align docs with the codebase), or the ticket-to-PR-ready loop — across engineering, content, evaluation, operations, and design categories, many contributed by named practitioners. The point is to give agents bounded, verifiable routines instead of open-ended instructions, so recurring work like changelogs, test coverage, or repo cleanup runs the same reliable way every time.

### lmcache
- Details: LMCache is an open-source KV cache management layer for LLM inference that turns the KV cache from throwaway state into persistent, reusable AI-native knowledge. Running as an engine-independent daemon, it offloads KV cache from GPU memory into a tiered hierarchy (CPU RAM, local disk, Redis/Valkey, S3-compatible storage, and more), cutting time-to-first-token and boosting throughput especially for long-context, multi-turn, and RAG workloads. It is vendor-neutral across serving engines (vLLM and others), hardware, and storage backends, with production observability metrics and features like non-prefix KV reuse via CacheBlend. Apache 2.0 licensed with around twelve thousand GitHub stars, it is backed in part by Tensormesh and integrated by projects including NVIDIA Dynamo.

### pi-shell-acp

Entwurf is a thin bridge that lets independent agent harnesses (pi, Claude Code, Codex, Copilot, OMP, Antigravity) address each other by stable garden ids and exchange messages or spawn visible sibling sessions, while each keeps its own auth, tools, and transcripts. ### es-git-pr-213
- Details: This pull request by monotykamary to toss/es-git (Rust bindings for libgit2) fixes diff.print() in the default Patch format, which was stripping the plus, minus, and space line-origin prefixes from hunk body lines, making the output unparseable for consumers that need to distinguish additions from deletions and context. The fix in src/diff.rs reads each line's origin and prepends it for content lines, while leaving already-formatted origins (file headers, hunk headers, EOF markers, binary notices) untouched, and it applies to all DiffFormat variants going through the print callback. The test plan updates the diff spec expectations and reports all 210 existing tests passing across 34 test files.

### pi-tool-repair
- Details: pi-tool-repair is a validate-then-repair extension for the pi coding agent that fixes the recurring set of tool-call mistakes open models make before tools execute. It repairs null optional fields, JSON-stringified arrays, bare strings where arrays are expected, wrong field names via an alias table (file_path to path, query to pattern, and dozens more), numeric strings, schema anchor bleed on models like Kimi K2, and optionally leaked tool-call grammar from families like DeepSeek DSML, Qwen, and GLM. Repairs run on pi's message_end hook against the live tool schemas and only commit when the result re-validates, so schema-valid input passes through untouched. Install with pi install npm:pi-tool-repair; the author reports DeepSeek V4 Pro beating Opus 4.7 in 6 of 10 internal evals with the layer enabled.

### fff-pr-593
- Details: This pull request by monotykamary to dmtrKovalenko/fff fixes the pi-fff extension's /fff-mode command, which previously only mutated an in-memory variable that was lost on /reload and session restart. The selected mode is now persisted through two complementary mechanisms: the PI_FFF_MODE environment variable, which survives /reload since the process stays alive, and pi.appendEntry('fff-mode', ...) writing to the session file, which survives full process restarts and is restored on session start. A follow-up commit simplified this to the appendEntry mechanism alone, and the user-facing notice was updated from "requires restart" to "requires /reload" now that reload actually works.
