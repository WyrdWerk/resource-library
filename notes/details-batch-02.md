### pi-typesafe
- Details: pi-typesafe (DevMortimer) puts TypeSafe's Jev judgment model inside the Pi coding agent. Jev answers typed questions — choice (which option fits, with probabilities), score (position on an ordered rubric), noul (probability a statement is true) — in well under a second for a fraction of a cent, returning calibrated numbers instead of prose. The package gives Pi three things: the `typesafe_evaluate` agent tool (opt-in per session via `/typesafe enable`) for batched structured judgments like triaging issue lists or scoring candidates against a rubric, a terminal playground (`/typesafe test`, `/typesafe playground`) that runs requests without touching model context, and a typed API so other extensions (like pi-warden) share one client, one key store, and one login prompt instead of each asking for a key. Spending is fenced with per-session attempt caps, daily request/token/USD caps that survive restarts, and a usage ledger; backends beyond TypeSafe itself include OpenRouter, CommandCode, and Liquid AI (whose free d1 model is slow enough to need longer timeouts). MIT.

### minicpm5-2b-pcd
- Details: An experimental inference package (monotykamary) applying Parallel Constrained Decoding (PCD) to the unchanged openbmb/MiniCPM5-2B weights — no training, RL, LoRA, or weight modification — for fast finite-choice classification and structured extraction on a 2B model. Token mode branches one question per field and projects the LM head only onto allowed token rows; sequence mode scores complete serialized candidates by normalized log-likelihood. Measured on one L40S in FP32: token PCD averaged 85.61ms versus 694.99ms for autoregressive JSON (8.1x faster), with 88.9% field accuracy versus 94.4% — and 100% schema-valid objects in both. The card is unusually honest about limits: accuracy equivalence is not established, returned probabilities are uncalibrated, sequence mode keeps length bias, and only closed flat objects (required fields, enums/booleans, no nesting or cross-field constraints) are supported. Includes a Modal scale-to-zero deployment path and a conservative FP32 configuration. Code MIT; weights Apache-2.0 (OpenBMB).

### argusagent
- Details: ArgusAgent (microsoft/ArgusAgent, 135 stars) is a persistent, reviewed multi-agent runtime for long-horizon research and engineering — agent work that can plan, execute, verify, pause, and continue beyond a single model turn. Its core idea is the Driver-Harness split: the Driver's seat (what to do next, whether the last result was any good, when to stop) is divided across four roles that may not do each other's jobs — Manager (stage transitions), Planner (next task + required evidence), Engineer (implementation), and Reviewer (read-only verdict). Because the worker can't grade its own work, nobody has to watch it: across 27 campaigns and 1,548 hours it needed a human research decision about once every 310 hours at 95–99% duty cycle. Improvements compound without retraining via scoped Skills and source-linked Wiki findings, and new domains ship as verticals (24 included). Native backends span Copilot CLI, Pi, Codex, Claude Code, Cursor, OpenCode, Grok Build, Qoder, and DeepSeek; interfaces include a Windows desktop app, terminal cockpit, web UI, and phone. Credentials, payment, irreversible actions, and publication always stop for a human. Technical report on arXiv (2608.05144). MIT.

### lfm2-5-2-6b-rlcd
- Details: LFM2.5-2.6B-RLCD (monotykamary) — an experimental inference-only package implementing Parallel Constrained Decoding (PCD) on unchanged LiquidAI/LFM2.5-2.6B weights. Instead of generating JSON tokens autoregressively, it prefills shared context once, forks the model's attention and convolution state per field, evaluates all allowed answers in parallel (projecting the output head only onto the relevant option-token rows), and serializes a typed JSON object in Python. Two modes: `token` (fast classifier-style per-field decisions, ~9.9x faster than AR JSON on 12 dev cases and 45.6x on a 28-field synthetic case on a single L40S) and `sequence` (full-sequence log-likelihood scoring reference). The card is unusually honest about limits: only 72.2% accuracy on six fresh audit cases vs 94.4% for autoregressive JSON, failed both high-cardinality probes, and the production accuracy gate was not met — returned probabilities are uncalibrated. Weights unchanged from upstream (LFM Open License v1.0, commercial revenue conditions); the PCD inference code is MIT. Includes Modal scripts, benchmarks with raw JSON evidence, and pytest coverage of cache/scoring equivalence. The `RLCD` name follows community naming, not TypeSafe/Jev's actual RL training.

### qwen-2-5-1b-rlcd
- Details: Qwen-2.5-1B-RLCD (harshatheg) — a high-throughput Parallel Constrained Decoding inference engine for structured extraction, decision routing, and categorical classification, tuned for Apple Silicon via MLX (benchmarked with mlx-community/Qwen2.5-1.5B-Instruct-4bit on an M4 Max, where it claims 5.6x-7.0x latency reductions over standard autoregressive decoding with 100% schema validity). The trick: single broadcast prefill of the context and schema into one KV cache, broadcast across all schema fields in parallel, sub-vocabulary logit slicing so only valid candidate token IDs are scored, calibrated softmax over the candidate slice, token-tree disambiguation for multi-token enum prefixes, and programmatic JSON assembly — no JSON parsing errors, ever. Includes a developer SDK (`StructuredSchema`/`FieldDefinition` for enums up to 255 choices and booleans), per-field confidence telemetry, a command-line benchmark runner with enterprise presets (fraud routing, code security audit, support triage, tariff classification), an interactive web visualizer comparing PCD vs autoregressive with hallucination detection, and a FastAPI server. Live side-by-side demo on Hugging Face Spaces. Apache 2.0.

### varve
- Details: Varve (monotykamary) is an experimental local-first, tiered time-series database in Rust — "time settles into layers." The design makes data aging a first-class concern without inheriting a full PostgreSQL server: Rust owns the write path, partitions, durability, and policy; Arrow/Parquet owns the columnar representation; DuckDB (v2 alpha) owns SQL execution. Data path: validated measurements → local WAL with fsync → hot rows and incremental rollups → sorted ZSTD Parquet segments → async publication to an S3-compatible object store. Features include append-only numeric time-series tables, stable hash shards with event-time windows, continuous count/sum/min/max/avg and OHLC rollups with retained-raw backfill, lifecycle jobs (flush, compaction, archive/eviction, expiration, GC), and Rust + TypeScript clients plus a JSON CLI, HTTP/WebSocket service, and opt-in PostgreSQL-wire compatibility. The README is explicit about boundaries: experimental v0.1, single-node only, not a production claim or distributed database. Apache-2.0.
