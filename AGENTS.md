# AGENTS.md — operating manual for the CheapInfra resource library

This repo is a curated, browsable archive of developer resources shared in the
CheapInfra Discord server's `#share-tech` channel, plus a curated inference-
provider section from the `#providers` channel (scope expanded 2026-09-25 at
the user's request). It is designed so that any agent with repo access can
extend it: collect a week, curate it, regenerate, push. This file is the full
context you need. Read it before touching anything.

## Ground rules (non-negotiable)

1. **Scope: `#share-tech` and `#providers` on CheapInfra only.** Never expand to other channels, servers, or sources.
2. **Collection is read-only.** No posting, reacting, clicking links, or DMing anyone. Ever.
3. **Privacy.** Sharer names are Discord usernames already visible in the channel; keep them, but never add real names, emails, or anything not in the message itself.
4. **No credentials in the repo.** Tokens, keys, and secrets never get committed.

## How data flows

```
Discord #share-tech  →  raw/share-tech_*.md, raw/daily-*.md  (raw logs, unfiltered)
                     →  notes/week-*.md, notes/daily-*.md     (curated: filtered + ~2-sentence briefs)
Discord #providers   →  raw/providers_*.md, raw/daily-*.md
                     →  notes/providers.md (backfill), notes/daily-*.md (## Providers)
Manual adds          →  notes/manual-*.md   (user-supplied links, no Discord browsing)
Live-page research   →  notes/details-*.md  (long-form "In detail" breakdowns, keyed by id)
                     →  scripts/build.py
                     →  index.html, data.json, weeks/, CHANGELOG.md, feed.xml,
                        og-image.png, robots.txt, sitemap.xml, llms.txt  (generated)
                     →  PR → merge to main → Cloudflare Pages auto-deploy

API v1 (machine-readable layer, same curated sources):
data.json + reviewed classification  →  scripts/migrate.py  →  catalog/resources/<id>.json
catalog/taxonomy/*.json (hand-edited vocabularies)
catalog/                             →  scripts/api_build.py  →  api/v1/ (resources.json,
                                                   taxonomy.json, facets.json, index.json)
                     →  scripts/validate_catalog.py  (schemas/ + taxonomy gate)
                     →  scripts/search.py        (deterministic lexical search over catalog/)
                     →  scripts/api_server.py    (stdlib-only local adapter for contract
                                                   tests; contract in api/openapi.yaml)
                     →  functions/api/v1/        (Pages Functions: JS port, edge_parity.py gate)
```

Commands for the API pipeline live in `docs/runbook.md` — follow them exactly,
don't improvise.

Tooling: Python 3.10+ with `pillow` (og-image), plus `pytest` and
`jsonschema==4.17.3` for tests/validation (newer jsonschema rewords an error
message `tests/test_schemas.py` asserts on). Everything else is stdlib.

## The `notes/` format

Each file is one collection batch. Sections assign entries to weeks:

```markdown
## Week: 13–20 Aug 2026        <- entries below go to this week
## Fold into week: 3–10 Sep 2026  <- boundary-day catch-ups for an existing week
## Providers                   <- entries below go to the Providers collection

### Resource Title
- URL: https://example.com/
- Posted by: username, 14 Aug 12:00 IST
- Category: ai-tool, github
- Brief: Two sentences, tops. What it is and why it's useful.
```

`notes/providers.md` uses a single `## Providers` section for the original
full-lifetime #providers backfill (earliest occurrence kept, deduped within
the channel and against the published site). Daily notes add new #providers
entries under their own `## Providers` section.

The website intermixes providers with other resources by share date, newest
first. Its sort control also offers oldest-first, name A–Z/Z–A, and category
A–Z/Z–A (first listed category, newest within each category). These are
presentation-only: source batches, exported data order, and week-filter
membership stay unchanged. Sort and filter choices are shareable in the URL;
Clear all restores the unfiltered, newest-first view.

Details sidecars (`notes/details-*.md`) use a different shape — a single
`## Details` section with one `### <record-id>` heading and a `- Details:`
bullet per resource (multi-line continuations are joined). Text is researched
from the live page after collection, ≤2000 characters, and flags vendor
claims as unverified. Ids with no fetchable page are simply omitted.

```markdown
## Details

### openrouter
- Details: Long-form breakdown of what it is, how it works, pricing, caveats.
```

- `build.py` auto-discovers every `notes/*.md`; week labels look like `13–20 Aug 2026` or `27 Aug–3 Sep 2026`. Weeks are ordered newest-first automatically.
- Keep a `## Dropped (and why)` section with bullets listing what you excluded and why — it's provenance, not clutter.

## Filter policy

**Keep:** AI tools, general tools, useful websites/webpages, GitHub repositories, and (from #providers) inference providers and provider comparisons — things a developer would actually use.
**Drop:** hype-only posts, exact duplicates, redundant announcement tweets when the underlying resource is already present, content with no usable resource (videos, memes), links with no context that can't be classified.
**Briefs:** ~2 sentences. Descriptions come from message text and embed previews — links are *not* opened during collection. Flag unverified claims from announcement posts as unverified.

## Category taxonomy (fixed set)

`ai-tool` · `dev-tool` · `github` · `web-app` · `article` · `providers`

Use one or two per resource. `providers` is for inference providers and
provider-comparison/analysis resources (the #providers channel). Do not invent
new categories without discussion — the site's filter chips and colors are
keyed to this set.

API facets are additive, never a replacement: `catalog/taxonomy/` holds separate
controlled vocabularies (resource-types, topics, use-cases, interfaces,
technologies, synonyms), so a resource can be a GitHub repo *and* an AI tool
*and* a dev tool without touching the six legacy labels. New classification
vocabulary goes in `catalog/taxonomy/*.json`; the six categories above stay
frozen.

## The boundary-date rule (important)

Discord's `after:`/`before:` search filters **exclude** the boundary dates. A search for `after:2026-08-27 before:2026-09-03` covers 28 Aug–2 Sep only. So:

- Always overlap weekly windows by a day, and
- Re-query missed boundary days separately (`after:2026-09-02 before:2026-09-04` covers 3 Sep), then fold the results into their weeks with `## Fold into week:` sections and deduplicate.

## Daily runs

Since 2026-09-26 a scheduled run collects both channels incrementally at
08:00 IST: `in:#share-tech has:link after:<D-2>` and
`in:#providers has:link after:<D-2>` (`after:` excludes its date, so this
re-covers yesterday by design; dedupe against published entries handles
repeats). Each run writes `raw/daily-<YYYY-MM-DD>.md` and
`notes/daily-<YYYY-MM-DD>.md` (a header noting sweep counts and newest
message covered, `## Week:` / `## Fold into week:` / `## Providers` sections,
and `## Dropped (and why)`), runs the full pipeline below, and opens a PR on
a `daily/<date>` branch.

## Adding a new week

1. **Collect** (read-only): run `in:#share-tech has:link after:<start> before:<end>` for the week, plus boundary-day catch-ups. Record author, date, message text/context, and every external URL. Save the raw table to `raw/share-tech_<YYYY-MM-DD>_to_<YYYY-MM-DD>.md`.
2. **Curate**: filter per the policy above, write ~2-sentence briefs, and save as `notes/week-<YYYY-MM-DD>_to_<YYYY-MM-DD>.md` using the format above.
3. **Regenerate**: `python3 scripts/build.py` — verify the resource counts it prints.
   Then refresh the catalog and API artifacts per `docs/runbook.md` §1
   (`scripts/migrate.py` with a reviewed classification for new ids,
   `scripts/api_build.py`, `scripts/validate_catalog.py`), refresh
   `tests/manifest.baseline.json`, and run the tests.
4. **Commit + push** on a branch and open a PR against `main` (see below).
5. Update this file only if a convention changed.

## Pushing

The repo's token is scoped to this repository only. Push with the GitHub API:

- **Empty repo:** use the Contents API — `PUT /repos/{owner}/{repo}/contents/{path}` with base64 content, one call per file.
- **Existing repo:** prefer a single commit via the git data API — create blobs, then a tree, then a commit, then update the branch ref.

Work lands through PRs: push a topic branch (`daily/<date>`, `batch-NN/...`,
`fix/...`) and open a PR against `main`; merging deploys. Several PRs touching
generated files at once will conflict — rebase and re-run the build rather
than hand-merging `index.html`/`data.json`. Never force-push `main`.

## Analytics

The Analytics tab is generated at build time from `data.json` — no JavaScript chart
libraries, just inline SVG. Charts: resources-per-week, top 10 sharers, stacked
category mix per week with a weekly/fortnightly toggle, all-time category mix, and a
spotlight on the top sharer's category breakdown. The "Providers" collection
appears as its own leading period (and `providers` as a category) in these
charts. Theme colors come from CSS variables, so charts follow the dark/light
toggle automatically. Never hand-edit the generated SVG; change the generator
functions (`vol_chart`, `stacked_chart`, `hbar_chart`) in `scripts/build.py` instead.

The third tab, **API**, documents the API v1 surface for humans and agents
(quick start, endpoints, params, record shape, conventions and errors,
machine-readable doc links). It is generated by
`scripts/build.py` like everything else — edit the `#apidocs` section and the
`llms.txt` template in `build.py` to change it; never hand-edit `index.html`.

## Deploying

The site is `index.html` (+ `data.json`, `feed.xml`, `og-image.png`, `robots.txt`, `sitemap.xml`, `llms.txt`). Any static host
works; it's built for Cloudflare Pages with no build command and the repo root as the
output directory.

**Important:** `scripts/build.py` has a `SITE_URL` constant (used for `og:image`,
the RSS channel link, and the canonical URL). It points at the custom domain
`https://cheapinfra-resources.wyrdwerk.com`; change it deliberately, then
re-run the build.

The dynamic `/api/v1/search` and `/api/v1/resources` routes are Pages Functions
in `functions/api/v1/` — they deploy automatically with the site (same repo-root
output, no build command). Verify with `scripts/edge_parity.py` against the
preview before merging to `main` (see `docs/runbook.md` §8).

## What NOT to do

- Don't hand-edit `index.html`, `data.json`, `weeks/`, or `CHANGELOG.md`.
- Don't hand-edit anything under `catalog/` or `api/v1/` — regenerate with
  `scripts/migrate.py` / `scripts/api_build.py`. New classification vocabulary
  belongs in `catalog/taxonomy/*.json`, never in the six frozen site categories.
- Don't edit or delete anything under `raw/`.
- Don't rename categories or change the `notes/` section-header format without updating `scripts/build.py`.
- Don't widen the collection scope, and don't break the read-only rule.
