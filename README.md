# CheapInfra Resource Library

A curated, browsable archive of developer resources shared in the [CheapInfra](https://cheapinfra.com) Discord server's `#share-tech` and `#providers` channels: AI tools, dev tools, websites, articles, GitHub repos, and inference providers, newest first. **310 resources** as of 4 Oct 2026; 218 of them carry a long-form "In detail" breakdown.

**Browse it:** <https://cheapinfra-resources.wyrdwerk.com/>. The site is a single `index.html` with no dependencies and no build step. You can open it locally or deploy it to any static host (it's built for Cloudflare Pages). It defaults to a black editorial theme (near-black background, serif headlines, mint-green accent), and a header toggle switches to light mode and remembers your choice. It has three tabs:

- **Library**: search, category and period filters, a Clear all button, and a sort control. By default every resource, providers included, is listed newest first by share date; you can also sort oldest first, by name, or by category. Cards with a researched breakdown expand on click.
- **Analytics**: weekly volume, top sharers, category mix over time (weekly or fortnightly), all-time mix, and a spotlight on the top sharer. Every chart is inline SVG with no libraries.
- **API**: human- and agent-facing docs for the JSON API: quick-start curls, endpoints, parameters, record shape, conventions, and errors.

Every view is shareable through the URL hash, e.g. `#view=api`.

## Coverage

- **#share-tech:** 221 resources in 17 weekly periods, from 4 Jun 2026 to the current week (1–8 Oct 2026).
- **#providers:** 89 inference providers and provider-analysis resources. The first batch covered the channel's whole lifetime from its creation on 20 Jul 2026; daily runs have kept it current since then.

Collection has run daily at 08:00 IST since 26 Sep 2026. Each run adds `raw/daily-<date>.md` and `notes/daily-<date>.md` and opens a PR. See [CHANGELOG.md](CHANGELOG.md) for the batch history.

## Methodology

- **Collection is read-only.** Collection uses Discord search (`has:link`, scoped to `#share-tech` or `#providers`), in weekly windows for the backfill and incremental `after:` sweeps for the daily runs. Nothing is posted or reacted to, nobody is DMed, and no links are clicked during collection.
- **Filtering.** Kept: AI tools, general tools, useful websites, GitHub repos, and inference providers that a developer would actually use. Dropped: hype-only posts, exact duplicates (the earliest occurrence wins), and redundant announcement tweets when the underlying resource is already listed. Every notes file keeps a `## Dropped (and why)` section.
- **Boundary dates.** Discord's `after:`/`before:` filters *exclude* the boundary dates, so boundary days are re-queried separately and folded into their weeks.
- **Briefs.** Every retained resource gets a ~2-sentence editorial brief based on the message text and embed preview. Claims that come from announcement posts are marked unverified. When a brief contains a caveat, it is lifted out and shown with a ⚠ marker.
- **Details.** Long-form breakdowns (`notes/details-*.md`) are researched from each resource's live page after collection, in a separate pass. Collection itself never opens links.

## Machine-readable API

The library is also served as data, through a read-only JSON API with no auth, open CORS, and ETag caching:

```bash
curl "https://cheapinfra-resources.wyrdwerk.com/api/v1/search?q=react+components&topic=frontend,design"
curl "https://cheapinfra-resources.wyrdwerk.com/api/v1/resources/openrouter"
curl "https://cheapinfra-resources.wyrdwerk.com/api/v1/facets.json"
```

| Endpoint | Returns |
|---|---|
| `GET /api/v1/search` | Deterministic lexical search with facet filters (CSV values: OR within a family, AND across families), inclusive `from`/`to` date bounds, `sort=relevance\|newest\|oldest\|title`, `fields`, `limit`, `cursor` |
| `GET /api/v1/resources` | All canonical records in stable order, paginated |
| `GET /api/v1/resources/{id}` | One record by its immutable id |
| `GET /api/v1/resources.json` | Static snapshot of every record in one array |
| `GET /api/v1/facets.json` | Every valid filter value with its record count |
| `GET /api/v1/taxonomy.json` | Label, definition, and aliases for every facet value, plus the synonym map |
| `GET /api/v1/index.json` | Manifest: version, build time, count, channels, `resources_sha256` |

Search ranks matches for `q`. Filters narrow a query but can't browse on their own, so to list everything in a facet, page `/resources` and filter client-side. The full contract, including headers, error codes, and schemas, is in [`api/openapi.yaml`](api/openapi.yaml). The in-site **API** tab and [`llms.txt`](llms.txt) summarize it.

How it's built: `catalog/` holds one canonical JSON record per resource plus the controlled taxonomy, and `scripts/api_build.py` generates `api/v1/` from it. The dynamic routes are Cloudflare Pages Functions in `functions/api/v1/`, a faithful port of the stdlib adapter `scripts/api_server.py`, and they read the same deployment's static assets. `scripts/edge_parity.py` proves the two stay identical by replaying the 40-query gold set and the full contract battery against any deployment. Search uses no vector database and makes no model calls. See [docs/runbook.md](docs/runbook.md) for the exact commands.

## Working on this repo

Read [AGENTS.md](AGENTS.md). It covers collection, the `notes/` formats, the category taxonomy, regeneration, and pushing. Tooling needs Python 3.10+ with `pillow` (for the social card), plus `pytest` and `jsonschema==4.17.3` for tests and validation. Everything else is standard library.

## Deploying

Any static host works. On Cloudflare Pages, create a project from this repo with no build command and the repo root as the output directory. The Pages Functions in `functions/` deploy automatically with the site.

## Contributing

See [CONTRIBUTING.md](CONTRIBUTING.md). In short, suggest resources through issues and send fixes as PRs against `notes/`. Everything else is regenerated from the notes, so changes belong there.
